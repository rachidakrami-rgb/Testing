# نظام إدارة عيادة الأخصائي النفساني

برنامج متكامل لإدارة عيادة أخصائي نفساني، مبني بتقنيات حديثة وتصميم احترافي متجاوب،
مع بوابة إلكترونية للمريض ونظام حجز بالتذاكر.

## المميزات

### الإدارة (دخول الطبيب)
- **تسجيل دخول آمن**: صفحة دخول موحدة يُحدد فيها نوع الزائر (طبيب / مريض)، الطبيب يدخل باسم مستخدم وكلمة مرور (مع كلمة مرور معماة وحماية ضد تجربة الاختراق).
- **لوحة تحكم** بأهم الإحصائيات مع رسم بياني، وبطاقة خاصة بطلبات الحجز الإلكتروني بانتظار التأكيد.
- **إدارة المرضى**: ملفات كاملة، أرشفة بدل الحذف النهائي حفاظاً على السجل الطبي، بحث سريع، ترقيم صفحات.
- **حجز المواعيد**: تأكيد/تعديل/إلغاء المواعيد حسب جدول المواعيد، فحص تلقائي لتعارض الأوقات، وسم الطلبات الإلكترونية والجلسات الخاصة.
- **تسجيل الزيارات**: الشكوى، التشخيص، العلاج، الوصفة، ملاحظات الجلسة، تقييم المزاج.
- **إدارة الأشعات والصور**: رفع وعرض وتنزيل (الملفات متاحة للطبيب المسجل فقط).
- **الفواتير والمدفوعات**: حسابات مالية دقيقة بـ Decimal، ترقيم فواتير فريد.
- **التذكير بالمواعيد** وسجل تدقيق كامل (من عدّل ماذا ومتى).
- **إشعارات بريد إلكترونية للمريض** عبر [Brevo](https://www.brevo.com) (مجانية 300 بريد/يوم): تُرسل تلقائياً عند **تأكيد** الموعد أو **تغييره** أو **إلغائه** من طرف الطبيب، مع سجل إشعارات كامل وزر اختبار في الإعدادات. الإرسال يجري في خيط خلفي فلا يبطئ النظام.
- **إشعارات تيليجرام** (قناة ثانية اختيارية): نفس إشعارات المواعيد تصل للمريضين المرتبطين ببوت العيادة ([@CLINIC_LARBI_bot](https://t.me/CLINIC_LARBI_bot))، مع ربط ذاتي عبر `/start كود_المريض` وwebhook واختبار إرسال من الإعدادات يفهم chat_id وكود المريض ورقم التذكرة مع لوحة تشخيص للبوت.
- **بوت تفاعلي بالأزرار**: بعد الربط يحصل المريض على قائمة أزرار Inline — مواعيدي القادمة، حالة آخر حجز، التواصل مع العيادة — وإشعارات المواعيد تصل بزر «متابعة حالة الحجز».
- **تذكير تلقائي بتأكيد الحضور**: كل يوم (الساعة قابلة للضبط من الإعدادات، افتراضياً 18:00) يرسل النظام تذكير مواعيد الغد عبر تيليجرام مع زري **✅ سأحضر / ❌ لن أحضر**. الردود تُسجل فوراً وتظهر في **بطاقة «تأكيدات حضور الغد»** بلوحة التحكم مع نافذة تفاصيل، وإذا اعتذر مريض تظهر للطبيب **نافذة تنبيه فورية (Toast)** حتى لو لم يكن في لوحة التحكم.
- **مراسلة الطبيب مباشرة**: صفحة عامة في بوابة المريض ترسل الرسالة إلى محادثة خاصة، ويرد الطبيب من لوحة التحكم فيصل الرد للمريض عبر تيليجرام أو البريد حسب القنوات المفعلة.
- **تنبيه فوري (Toast)**: عند وصول أي رسالة جديدة من مريض (بوابة أو تيليجرام) تظهر نافذة منبثقة في لوحة الطبيب خلال ثوانٍ مع مقتطف الرسالة ورابط لفتح المحادثة، وتحديث تلقائي لعداد غير المقروء كل 10 ثوانٍ.
- **رمز QR لربط المرضى**: زر QR في قائمة المرضى وبطاقة جاهزة في ملف كل مريض غير مرتبط تعرض رمزاً يحمل رابط الربط العميق (t.me/البوت?start=كود_المريض) — يمسحه المريض بكاميرا هاتفه فيفتح البوت ويرسل أمر الربط تلقائياً دون كتابة أي أمر، مع نسخ الكود والرابط وحفظ الرمز كصورة PNG للطباعة.
- **الإعدادات**: بيانات العيادة، جدول العمل (البداية/النهاية، مدة الجلسة، أقصى عدد حجوزات يومياً، أيام الراحة)، مخصص مصاريف النقل، مفاتيح Brevo، تغيير كلمة المرور.

### بوابة المريض (عامة دون حساب)
- **طلب حجز موعد**: يعرض للمريض الأوقات المتاحة فقط وفق جدول الطبيب، ويحصل على **رقم تذكرة**.
- **متابعة التذكرة من واجهة الدخول**: إدخال رقم التذكرة يظهر حالة الحجز (قيد المراجعة/مؤكد/ملغي...) وتاريخه وساعته.
- **جدول المواعيد المتاحة**: استعراض 14 يوماً قادمة بالأوقات المتاحة لحظياً.
- **طلب جلسة خاصة** خارج أوقات العمل مع التكفل بمصاريف النقل (يحدد الطبيب المبلغ عند التأكيد).

## المعمارية والأمان

| الجانب | التنفيذ |
|--------|---------|
| Backend | Python + Flask (Blueprints جاهزة للتوسع، حالياً ملف منظم بمقاطع) |
| Database | SQLite عبر SQLAlchemy + ترحيل أعمدة تلقائي لقواعد البيانات القديمة |
| الأمان | رمز CSRF يُحقن من الخادم في كل النماذج، حماية ضد تجربة كلمات المرور، حماية ملفات الرفع، SECRET_KEY من متغير بيئة `CLINIC_SECRET_KEY` |
| المال | `Decimal` عبر `db.Numeric(10,2)` بدقة مالية كاملة |
| Frontend | Bootstrap 5 RTL، Chart.js، Font Awesome، خط Cairo |

## تدفق الحجز الإلكتروني

1. المريض يفتح `/portal` ويختار «طلب حجز موعد».
2. يرى الأوقات المتاحة فقط (حسب ساعات العمل ومدة الجلسة وأقصى عدد حجوزات يومياً وأيام الراحة والحجوزات القائمة).
3. عند الإرسال يُنشأ موعد بحالة **«بانتظار التأكيد»** ويحصل على رقم تذكرة `TK-XXXXXX`.
4. الطبيب يرى الطلب في لوحة التحكم وصفحة المواعيد، ويؤكده أو يعدّل وقته أو يلغيه.
5. المريض يتابع الحالة في أي وقت بإدخال رقم التذكرته من واجهة الدخول.
6. عند تأكيد الموعد أو تغييره أو إلغائه يُرسل بريد إلكتروني تلقائي للمريض (إن كان لديه بريد مسجل والخدمة مفعّلة من الإعدادات).

## تفعيل إشعارات البريد (Brevo)

1. أنشئ حساباً مجانياً على [brevo.com](https://www.brevo.com) (300 بريد يومياً مجاناً).
2. من **Senders & IP** أضف بريد العيادة كمُرسِل موثّق.
3. من **SMTP & API → API Keys** أنشئ مفتاحاً وانسخه.
4. في النظام: **الإعدادات → إشعارات البريد الإلكتروني** → فعّل الخدمة، الصق المفتاح، أدخل بريد المرسل واسمه، ثم احفظ واستخدم زر **اختبار**.
5. المريض يحصل على إشعار فقط إذا كان لديه بريد إلكتروني مسجل (حقل البريد متاح في نموذج الحجز الإلكتروني وملف المريض).
6. كل الإشعارات (أُرسلت / فشلت / تجاوزت) تُسجل في صفحة **سجل الإشعارات**.

## تفعيل إشعارات تيليجرام (قناة اختيارية)

قناة ثانية للمريضين الذين يفضلون تيليجرام، تعمل **بنفس لحظة إشعارات البريد** (تأكيد / تغيير / إلغاء الموعد) وبنفس سجل الإشعارات:

1. أنشئ بوتاً من [@BotFather](https://t.me/BotFather) واحتفظ بالتوكن (بوت العيادة الحالي: [@CLINIC_LARBI_bot](https://t.me/CLINIC_LARBI_bot) وتوكنه مضبوط افتراضياً، ويمكن تغييره من الإعدادات).
2. اربط المريض بالبوت بإحدى طريقتين:
   - **تلقائياً**: يفتح المريض رابط البوت ويرسل `/start كود_المريض` (مثال: `/start P01001`) — يُحفظ `chat_id` الخاص به تلقائياً عبر endpoint `/telegram/webhook`.
   - **يدوياً**: من ملف المريض → تعديل → أدخل `chat_id` مباشرة (تحصل عليه من رابط `getUpdates` بعد أن يضغط المريض Start).
   - **برمز QR (الأسهل)**: من قائمة المرضى أو ملف المريض غير المرتبط — زر QR يعرض رمزاً يمسحه المريض بكاميرته فيُرسل أمر الربط تلقائياً.
3. بعد نشر التطبيق على رابط عام: **الإعدادات → ضبط Webhook على الرابط الحالي** (أو استدعِ `setWebhook` يدوياً على `https://api.telegram.org/bot<TOKEN>/setWebhook?url=<رابط_الموقع>/telegram/webhook`).
4. في النظام: **الإعدادات → إشعارات تيليجرام** → فعّل الخدمة، ثم استخدم زر **اختبار** (يقبل `chat_id` أو كود مريض).
5. بعد ربط المريض تُرسل له الإشعارات تلقائياً عبر القناتين معاً؛ من ليس لديه بريد أو تيليجرام لا يتأثر، ويُسجل التجاوز في سجل الإشعارات.
